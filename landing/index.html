Feedxcavator reads RSS feeds and ordinary web pages, lets you reshape what it finds with a few lines of your own code, and serves the result as a fresh feed for your reader.

01what-it-is

A feed is only as useful as what you can do to it. Feedxcavator sits between a source and your reader, and whatever passes through is yours to change.

in

Take almost anything

An existing RSS feed, or the plain HTML of a site that never offered one. Point at the headlines and it slices the page into items.

through

Change it however you like

Sort, filter, merge, rewrite, translate. There are no checkboxes to hit a wall against: the transformation is a small program you write.

out

Serve it in any shape

RSS, JSON Feed, plain JSON or EDN, with live push to readers that support it, so new items arrive the moment they exist.

my-first-feed feed definition · yaml
title: Daily Digest
suffix: daily-digest
source: https://example.com/news
selectors:
  item:  article
  title: h2
  link:  h2 a
  image: img::src-lazy||src
# extractor: my-extractor   (only if selectors are not enough)
served at
  • http://localhost:10000/feed/daily-digest

02how-it-works

You describe. It does the rest.

You write

  1. A feed definition in plain YAML: where the page is, and ordinary CSS selectors that point at the headlines, links and pictures.
  2. An extractor, a small function, but only when selectors alone can’t do the job.

Feedxcavator takes the rest

  1. Fetching the pages, on request or on a schedule.
  2. Serving the finished feed at a stable URL.
  3. Pushing new items to readers the moment they appear (WebSub).

03your-rules

The last mile is a program.

Selectors get you most of the way. For everything else you write an extractor: a short function that receives a feed definition and returns whatever headlines you want it to.

  • Written in the browser, in the same console that manages your feeds.
  • Fetch other pages, follow links, combine several sources into one feed.
  • Test a change on the spot and see the resulting feed right underneath.
price-drops extractor
;; one headline per listing: "name — price"
(defextractor price-drops [feed]
  (let [page (api/fetch-url (:source feed) :as :html)]
    (for [card (?* page [:div.listing])]
      {:title (str (<t (?1 card [:h3]))
                   " — "
                   (<t (?1 card [:.price])))
       :link  (:href (?1a card [:a]))})))
produces
  • Juno-60, fully serviced — $1,450
  • Minimoog reissue — $2,900
  • Drum machine lot — $180

04unusual-sources

When a site won’t play along.

Some pages hide behind scripts, logins or clever layouts. So the digging does not have to happen inside Feedxcavator at all.

External scripts
Feedxcavator can expose small web endpoints. A script in any language, running anywhere, can pick up a feed, do the awkward part, and post the finished result back.
Browser add-ons
Let an add-on do the visiting and copying inside a real browser session, then hand what it found to Feedxcavator to shape and publish.
Background tasks
Slow extractions run on a schedule instead of on demand. The finished feed is stored and served instantly whenever a reader asks.

05formats

One item, several shapes.

Pick the output that suits the reader — or the next program in your chain. Plain JSON is there too, for when a feed is only an intermediate step.

rss

<item>
  <title>Juno-60</title>
  <link>https://…/juno</link>
</item>

json feed

{"items": [
  {"title": "Juno-60",
   "url": "https://…/juno"}
]}

edn

[{:title "Juno-60"
  :link  "https://…/juno"}]

06fine-print

Built for tinkering, not for everyone. Feedxcavator is an experiment. It is not a hosted service and not a one-click app for end users.

  • You run it yourself, on your own machine, with Java 17 or newer.
  • The interesting parts are written in Clojure, so expect to read a little code.
  • Rough edges are part of the deal. Poke around in the live demo before you commit.
